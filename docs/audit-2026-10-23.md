## Security controls and dispositions

- The final 4-key pair rechecks permissions/focus and uses `postToPid`. Identity requires both the exact protected system path and bundle ID; Campo additionally requires `SpotlightSearchField`. Spoofing a display name or ordinary cross-app focus switching does not bypass these controls (`MacSpotlightKeyboard.swift:39–46,69–109`). AX downcasts follow Core Foundation type checks.
- Core MainActor isolation, `isRunning`, bounded waits, cancellation checks and cleanup installed before Command-down protect the chord lifecycle (`ClipboardHistoryAction.swift:86–118`). A01 is a real native allocation gap rather than a missing `defer`.
- No first-party pasteboard reads, AX value reads, clipboard persistence, networking or telemetry were found. Preference storage and login registration use `UserDefaults`/`SMAppService`, not clipboard data (`AppModel.swift:24–109`).
- Release version is validated before path use, subprocesses receive argument lists, archives come from `git archive` and extraction uses `filter='data'`. Workflow input passes through quoted environment variables; write authority is restricted to the separate manually dispatched release job, which creates a draft (`prepare-release.py:28–139`; `release.yml:21–60`).
- Ad hoc signing, no notarization, no App Sandbox and readable Action major tags are explicit project decisions, not newly discovered vulnerabilities. The Xcode template's unused iOS-only settings are inactive under `SUPPORTED_PLATFORMS = macosx`; removing them alone would be cosmetic.
- Localization catalogs contain English/German values and matching placeholders. Dynamic package errors use the package resource bundle. The interface was reviewed statically; historical UI screenshots/tests do not establish current visual acceptance.
- KeyboardShortcuts is pinned to version `3.1.0`, revision `772133d9dbe800fdac0473226822994c5c162c58`. The [upstream release](https://github.com/sindresorhus/KeyboardShortcuts/releases/tag/3.1.0) matches that revision. The public repository-advisories API returned zero published advisories on October 23. This narrow check does not establish that all advisory databases or the complete upstream implementation are audited.
- No new substantive UI, architecture or privacy contradiction was established. Historical acceptance records are explicitly bounded. Swift CodeQL coverage remains absent as documented; green Python/Actions scans are not Swift coverage.

## Correction evidence

- A01/A05: native adapter retains a preallocated release event, with internal creation/posting injection and no public protocol change. Native allocation-failure cases send nothing; cleanup allocates nothing and is idempotent. Core tests cover final focus/permission loss, already-cancelled requests, post-error recovery, existing overlap, deadlines and event order. The fake final-operation guard models the adapter contract; it does not prove live AX behavior.
- A02/A04: SPDX checks require declaration lines rather than arbitrary substrings, validate sidecars themselves and report missing required files or unreadable sidecars as errors. The actual SPDX header is present. The unreachable repeated sidecar branch is removed. Malformed catalogs, missing resources and placeholder mismatches have isolated regression fixtures.
- A03: disposable staging is removed on success/failure; completed output is renamed into place only after archive/checksum/note generation. Existing output is refused. The tests exercise real `ditto`, `git archive`, tar/ZIP and checksum operations with tiny fixtures; native build/signature operations are intercepted in these fixtures. Exact dependency source is included; dirty or revision-mismatched dependencies are rejected.
- A06: normal Renovate limits are explicit (`3` concurrent, `2` hourly); documentation records that security alerts bypass these limits. JSON/resource validation passes. Hosted bot behavior remains outside the source-level claim.
- Regression proof: running the new relevant tests against the old pre-fix scripts (`35502ab`) produces the expected SPDX false-positive/missing-file failures and packaging partial-output/stale-stage failures. The same cases pass against the corrected scripts.

## Remaining acceptance boundaries

Real keyboard delivery, permission mutation, login/sign-out, Gatekeeper/quarantined installation and interactive UI testing are excluded by the user. Focus verification and event delivery are not atomic OS operations. A successfully posted event is not proof that Spotlight opened history. Unknown runner hosting/isolation, branch controls, private reporting availability and hosted Renovate behavior require external evidence; the audit does not infer those from YAML or historical records. Complete third-party source auditing is outside this first-party inventory.

These limits do not block the selected static/build/core-test audit, but installation/login/UI acceptance remains **not verified**. No merge or release publication is part of this work.
